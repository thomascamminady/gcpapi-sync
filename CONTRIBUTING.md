# Contributing

## Setup

```bash
uv sync
uv run pre-commit install
```

`uv sync` creates `.venv` with every development tool pinned by `uv.lock`. The
pre-commit hooks run on every commit (and the tests on every push); CI runs the same
hooks, so a green local run means a green CI run.

## Quality bar

- `ruff format` and `ruff check` with **all** rules enabled.
- `ty check` with **every** rule as an error, and `mypy --strict`, over `src`, `tests`
  and `scripts`.
- **No suppression comments** (`noqa`, `type: ignore`, `ty: ignore`, coverage
  pragmas). A hook rejects them; change the code instead. The few justified
  exceptions are scoped rules in `pyproject.toml`, each with a comment.
- No free-form `dict`s or `Any` in the public API; `tests/test_models.py` enforces this
  for every response model.
- Branch coverage of at least 99%, on Python 3.11 to 3.14, on Linux, macOS and
  Windows, and against the lowest supported dependency versions.

## Tests

```bash
uv run pytest                 # everything except live tests
uv run pytest -m live         # against the real API (needs a key)
uv run pytest --cov           # with coverage
```

Unit tests talk to an in-process fake API (`tests/helpers.py`); most client tests run
twice, against the sync and the async client. Fixtures in `tests/fixtures` are real
responses anonymized with `scripts/scrub_fixture.py`. Always review a scrubbed
fixture before committing it, and never commit raw responses: they are personal
health data.

## Models and API drift

`src/gcpapi_sync/models/_generated.py` and `spec/endpoints.json` are generated by
`scripts/generate_models.py` from the OpenAPI document embedded in Garmin's Swagger
page. Corrections for places where the live API disagrees with the spec
(`EXTRA_FIELDS`, `NEW_SCHEMAS`, `FIELD_SCHEMAS`, ...) are in that script; each one
must be backed by a live observation.

The **API drift** workflow runs every Monday:

1. It regenerates the models and the endpoint surface from Garmin's current spec. If
   anything changed it opens a pull request with the diff, the generator's warnings
   and the test results. `tests/test_package.py` fails when an endpoint appears that
   no client method wraps, or when the client sends a parameter the spec no longer
   documents.
2. If the `GARMIN_PERSONAL_API_KEY` repository secret is set, it runs the live tests,
   which fail when Garmin returns fields the models do not know or when a request no
   longer validates. A failure opens an issue labelled `api-drift`.

Personal API keys expire after at most a year; renew the secret before it does.

## Documentation

API documentation is built with [pdoc](https://pdoc.dev) from the docstrings
(Google style) and published to
[camminady.dev/gcpapi-sync](https://camminady.dev/gcpapi-sync/)
on every push to `main`. To preview it locally:

```bash
uv run --group docs pdoc gcpapi_sync gcpapi_sync.exceptions gcpapi_sync.cli --docformat google
```

## Releases

1. Update `version` in `pyproject.toml` (`uv version --bump minor`) and move the
   `Unreleased` entries in `CHANGELOG.md` under the new version.
2. Commit, then tag and push: `git tag v0.2.0 && git push origin v0.2.0`.

The release workflow tests and builds the sdist and wheel, publishes them to
[PyPI](https://pypi.org/project/gcpapi-sync/) with
[trusted publishing](https://docs.pypi.org/trusted-publishers/) (no API token is
stored anywhere; PyPI trusts the `release.yml` workflow in the `pypi` environment),
and attaches the same files to a GitHub release.
